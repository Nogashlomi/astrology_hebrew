# Hebrew Astrological Manuscripts, 1250–1450

This research project harvests and analyzes catalogue records and digitized page images of Hebrew manuscripts
on astrology dated 1250–1450, as catalogued in Ktiv (National Library of Israel).

Records come from the NLI Alma catalogue through its public SRU endpoint. Page images come from NLI IIIF manifests.
The pipeline and visualizer are copied from the Hebrew Sacrobosco project (`../hebrew_sacrobosco_project`) and adapted;
the two projects are independent.

---

## Which manuscripts are in the corpus (step 1)

1. **Search**: every manuscript record (`type_of_record = t`) with *אסטרולוגיה* or *Astrology* anywhere in it, plus the
   subject heading *Astrology*.
2. **Tagged astrology**: the word is in a subject heading (MARC 650/651/655/690), in a Ktiv subject note
   ("נושא נוסף: מדעים. אסטרולוגיה") or in the title (245/246). A word found only in a free-text note does not count.
3. **Hebrew**: Hebrew or a Jewish language in Hebrew script (Judeo-Arabic, Ladino, ...), or a Hebrew script type
   recorded in 958 (e.g. "ספרדית").
4. **Dated 1250–1450**: the record's date range overlaps 1250–1450. The date is read from 260/264 $c (Gregorian years
   such as "קנ"ב (1392)" first, then centuries such as "מאה י"ד", "סוף מאה ט"ו", "מאות י"ד-ט"ו"), else from MARC 008.
   A century-only date counts when the century overlaps the period: "מאה י"ג" (1200–1299) and "מאה ט"ו" (1400–1499)
   are in, "סוף מאה ט"ו" (about 1467–1499) is out.

Every harvested record, with a column for each filter, is in `data/metadata/raw/ALL__deduped.csv`; the corpus is
`MANUSCRIPTS_ONLY.csv`; counts per search and per filter are in `_SUMMARY.csv`.

## Directory structure

```text
hebrew_astrology_project/
├── code/
│   ├── paths.py                      shared folder locations, used by every step
│   ├── 01_scrape_metadata.py         search Ktiv/NLI and choose the corpus → data/metadata/raw/
│   ├── 02_download_manuscripts.py    download page images → data/manuscripts/
│   ├── 03_organize_metadata.py       tidy metadata for the visualizer → data/metadata/clean/
│   ├── 04_extract_illustrations.py   crop illustrations with CorDeep + their metadata → data/illustrations/
│   ├── 05_cluster_illustrations.py   group illustrations by visual similarity → data/clusters/
│   ├── 06_build_visualizer.py        build the HTML tool → visualizer/
│   └── visualizer_template/          index.html, app.js, style.css (edit these, not visualizer/)
├── data/
│   ├── metadata/raw/                 marcxml/, ALL__deduped.csv, MANUSCRIPTS_ONLY.csv, _SUMMARY.csv,
│   │                                 MANUSCRIPTS_IMAGES_INDEX.csv, PAGE_LEVEL_METADATA.csv, DOWNLOAD_FAILURES.csv
│   ├── metadata/clean/               visualizer_data.json
│   ├── manuscripts/                  <mms_id>_<library>_<shelfmark>/NNNN.jpg + metadata.json
│   ├── illustrations/                <manuscript folder>/<page>_<class>_NN.jpg + illustrations.csv
│   └── clusters/                     clusters.csv, clusters.json (data only, no images)
├── visualizer/                       built site (generated by step 6)
├── external/sphaera-cordeep/         CorDeep detector, cloned read-only (not part of this repo's git)
└── requirements.txt
```

The page images (about 6.6 GB) are not in git. They are kept in Google Drive (My Drive › hebrew_astrology_project ›
manuscripts), and `data/manuscripts` is a link to that folder as Google Drive for desktop shows it, so pages are fetched
from Drive when opened. Without that link, step 2 downloads them again from Ktiv. Everything else in `data/`, including
the illustration crops, is in the repository.

The NLI **MMS ID** (18 digits) links everything: catalogue rows, manuscript folder names, `metadata.json`, page index
and illustration IDs.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Step 4 also needs **CorDeep** (YOLOv5 trained on printed *Sphaera* editions by MPIWG), shared at
https://github.com/Euclides-EM/sphaera-cordeep. It has its own environment (Python 3.12 + torch), managed by
[uv](https://docs.astral.sh/uv/):

```bash
git clone https://github.com/Euclides-EM/sphaera-cordeep.git external/sphaera-cordeep
git -C external/sphaera-cordeep remote set-url --push origin DISABLED-read-only-copy
cd external/sphaera-cordeep && uv sync
```

The push URL is disabled so nothing can be sent back to the original repository. `external/` is git-ignored.
CorDeep was trained on printed books, so on manuscripts it misses some drawings and boxes some things that are not.

## Running the pipeline

Run from the project root, in order:

```bash
python code/01_scrape_metadata.py                      # catalogue harvest and corpus filters
python code/02_download_manuscripts.py                 # page images; resumes, skips pages already on disk
python code/03_organize_metadata.py
python code/04_extract_illustrations.py                # CorDeep; --only <folder>, --conf, --overwrite
python code/05_cluster_illustrations.py
python code/06_build_visualizer.py
```

Ktiv's image server sits behind Cloudflare, which blocks generic user agents; step 2 sends its own. Images restricted
to on-site viewing answer "no permissions" and are recorded as `restricted`, not bypassed. If Ktiv is down
(Cloudflare error 520), steps 1 and 3 still work from the catalogue; run step 2 later.

Then serve the project over HTTP and open the visualizer (opening the file directly does not work):

```bash
python3 -m http.server 8766
```

and go to http://localhost:8766/visualizer/index.html. The map tab needs internet access (Leaflet and OpenStreetMap tiles).
